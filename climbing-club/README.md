# מערכת ניהול חוג טיפוס לילדים

ניהול ילדים, קבוצות, מפגשים, נוכחות, גבייה, תשלומים והפקת קבלות – במערכת אחת, בעברית, RTL, למחשב ולטלפון.
מבוססת על מסמך האפיון (ראו `docs/`). מיועדת לספיר ויהלי: מזינים פעם אחת תאריך מפגש, מסמנים נוכחות, ובסוף החודש עוברים על החיובים, מאשרים הודעות, קולטים תשלומים ומאשרים קבלות.

## התקנה והרצה (5 דקות)
```bash
cd climbing-club
pip install -r requirements.txt
python run.py                 # http://127.0.0.1:8000
```
בכניסה הראשונה המערכת מבקשת ליצור את משתמש מנהל המערכת. אחר כך: הגדרות → משתמשים → הוספת "מנהלת" ו"תפעולית".

נתוני הדגמה (קבוצות ראשון/רביעי, 6 ילדים עם הסדרים שונים, לוח ספטמבר 2026 עם חג והעברה):
```bash
python scripts/seed_demo.py   # מוחק את המסד הקיים! משתמשים: admin / sapir / yahli, סיסמה demo1234
```

Docker:
```bash
docker build -t climbing-club . && docker run -p 8000:8000 -v $(pwd)/data:/app/data climbing-club
```

## הגדרות סביבה (`.env`)
| משתנה | ברירת מחדל | משמעות |
|---|---|---|
| `CLUB_DATA_DIR` | `./data` | תיקיית המסד, האסמכתאות והגיבויים |
| `CLUB_SECRET_KEY` | נוצר אוטומטית | מפתח חתימת העוגיות |
| `CLUB_COOKIE_SECURE` | `0` | `1` מאחורי HTTPS |
| `CLUB_RECEIPT_PROVIDER` | `mock` | `mock` / `manual` / `ypay_api` – ראו `docs/05-ypay-integration.md` |
| `YPAY_API_BASE_URL`, `YPAY_API_KEY`, `YPAY_API_SECRET`, `YPAY_SANDBOX` | | ל-`ypay_api` בלבד |
| `ANTHROPIC_API_KEY`, `CLUB_OCR_MODEL` | | פענוח צילומי מסך של אישורי תשלום (אופציונלי) |

## מבנה
```
app/
  models.py            מודל הנתונים (ראו docs/02)
  auth.py              כניסה, הצפנת סיסמאות, הרשאות לפי תפקיד
  audit.py             יומן שינויים
  services/            הלוגיקה העסקית: calendar, attendance, billing, messages, payments, receipts, month_close, backup, ocr
  services/ypay/       ספקי קבלות: mock / manual / ypay_api
  routers/             מסכי המערכת (FastAPI + Jinja2)
  templates/ static/   תבניות HTML בעברית, CSS ו-JS מקומיים (ללא תלות באינטרנט)
docs/                  אפיון מפורט: זרימה, מודל, מסכים, חישוב, YPAY, תוכנית בדיקות
scripts/seed_demo.py   נתוני הדגמה
tests/                 pytest (python -m pytest tests -q)
```

## הרשאות
| תפקיד | יכול |
|---|---|
| משתמשת תפעולית | צפייה, דיווח נוכחות, קליטת תשלומים, סימון הודעה כנשלחה |
| מנהלת | כל האמור + ילדים, לוח, חיובים, אישור/הפקת קבלות, הגדרות, סגירת חודש, פרטי בנק ואסמכתאות |
| מנהל מערכת | כל האמור + משתמשים, גיבוי ושחזור |

## שלבי הפיתוח (לפי האפיון) ומצבם
| שלב | מצב |
|---|---|
| 1 תשתית ומאגר | ✔ כרטיסי ילדים/הורים/משלמים, קבוצות, היסטוריית תעריפים, הגדרות קבלה |
| 2 לוח שנה ונוכחות | ✔ יצירה חודשית, חגים, העברות, מועדים חריגים, סימון מהיר, תיקון מתועד |
| 3 חישוב חודשי וגבייה | ✔ 4 שיטות חיוב, חריגים, התאמות, הודעות וואטסאפ, תשלומים ידניים, שיוך חלקי/רב-חודשי |
| 4 הפקת קבלות | ✔ תצוגה מקדימה, אישור מפורש, מניעת כפילות, ספק mock/manual; שלד `ypay_api` ממתין לאימות ה-API |
| 5 פענוח מסמכים | ✔ העלאה, חילוץ (עם מפתח API), טופס בדיקה, כפילויות; ללא מפתח – הזנה ידנית |
| 6 אוטומציות מתקדמות | ○ שליחה מתוך המערכת – רק אחרי בדיקות; כרגע wa.me + סימון "נשלחה" |

## אבטחה
סיסמאות ב-PBKDF2-SHA256; עוגיית session חתומה; הרשאות בכל נתיב; פרטי בנק ואסמכתאות למורשים בלבד; סודות רק ב-`.env`; יומן שינויים לנוכחות/חיובים/תשלומים/קבלות; גיבוי ושחזור מהמסך. מומלץ להריץ מאחורי HTTPS (`CLUB_COOKIE_SECURE=1`).
