# 5. תוכנית חיבור ל-YPAY, כולל מגבלות ידועות

## מצב הידע (נכון לכתיבת מסמך זה)
לא אומתה מול YPAY אף אחת מהשאלות הטכניות שבאפיון. **אין להניח שקיים API רשמי** או שמותר לבצע אוטומציה באתר. לכן המערכת בנויה בשכבת ספק ניתנת להחלפה (`app/services/ypay/`), והלוגיקה העסקית (הכנה, תצוגה מקדימה, אישור, מניעת כפילויות, מעקב סטטוס) אינה תלויה בספק.

## שאלות לבירור מול YPAY (רשימת תיוג)
- [ ] האם קיים API רשמי להפקת קבלות? תיעוד, אימות (API key / OAuth), כתובת בסיס.
- [ ] אילו שדות ניתן להעביר: שם משלם, ת.ז., מייל, תאריך, סכום, אמצעי תשלום, אסמכתא, שורות פירוט, הערות חופשיות.
- [ ] מה חוזר: מזהה מסמך, מספר קבלה, סטטוס, קישור/PDF.
- [ ] שליחה למייל דרך YPAY (endpoint נפרד? דגל בבקשת ההפקה?).
- [ ] סביבת בדיקות (sandbox) וקבלות דוגמה.
- [ ] טיפול בשגיאות, קצב בקשות, ניסיון חוזר, ותמיכה ב-Idempotency-Key.
- [ ] תמיכה בקבלות נפרדות לכל מפגש (נפח: כמה קבלות בחודש).
- [ ] ביטול/זיכוי קבלה – האם דרך API או ידני בלבד.
- [ ] תנאי השירות: האם אוטומציה דרך הממשק (דפדפן) מותרת.

## שלוש דרכי חיבור (נבחרות במשתנה `CLUB_RECEIPT_PROVIDER`)

| ספק | מתי | מה קורה בלחיצה "הפקה" |
|---|---|---|
| `mock` (ברירת מחדל) | פיתוח, הדגמה, בדיקות | סימולציה: מספר קבלה `SIM-…`, ללא קריאה חיצונית |
| `manual` | **אם אין API** – מסלול חצי-אוטומטי | המערכת מכינה את כל נתוני הקבלה בתצוגה מקדימה (להעתקה לאתר YPAY); המשתמשת מפיקה באתר ומזינה את מספר הקבלה; המערכת רושמת סטטוס "הופקה" ומונעת הפקה כפולה |
| `ypay_api` | לאחר אימות API | `YPayApiProvider` שולח POST עם `Idempotency-Key`, מפענח מספר קבלה/PDF, ושולח מייל דרך YPAY אם נתמך |

`ypay_api` נכתב כשלד: `_build_payload` ו-`_parse` הן הנקודות היחידות שיש להתאים לתיעוד בפועל. הסודות (`YPAY_API_KEY`, `YPAY_API_SECRET`) נקראים מקובץ `.env` בלבד ואינם נשמרים במסד.

## מניעת הפקה כפולה
1. לכל קבלה `idempotency_key` ייחודי במסד (אילוץ UNIQUE) – הכנה חוזרת של אותו תשלום אינה יוצרת קבלה נוספת.
2. הפקה אפשרית רק ממצב `approved`; קבלה במצב `issued`/`sent` חוסמת הפקה חוזרת ברמת השירות.
3. הכפתור מתבטל אחרי לחיצה (JS) ונדרשת תיבת אישור.
4. המפתח נשלח לספק כ-`Idempotency-Key` – כשל תקשורת וניסיון חוזר מחזירים את אותה קבלה.
5. כשל מסומן `failed` עם הודעת השגיאה; ניסיון חוזר דורש אישור מחדש.

## תנאי לשחרור לסביבת אמת
* השוואה של 3 קבלות לפחות מכל סוג (מרוכזת, לכל מפגש, היכרות, עם קופ"ח) מול קבלות אוגוסט – שדה מול שדה.
* הרצה ב-sandbox של YPAY עם `YPAY_SANDBOX=1`.
* בדיקת מניעת כפילות: לחיצה כפולה, ניתוק רשת באמצע, הכנה חוזרת.
* אישור מפורש של המשתמשת לכל קבלה. שליחה אוטומטית רק לאחר שהוכח שההפקה מדווחת הצלחה באופן אמין.
